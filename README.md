# Подъезд робота к зарядной станции по ArUco-маркеру

Робот по видео с камеры находит ArUco-маркер на зарядной станции, вычисляет
расстояние и угол до него и подъезжает, пока не окажется на заданной
дистанции. Команды скорости отправляются как `geometry_msgs/Twist` в топик
`/cmd_vel` (ROS 2), а дальше их превращает в движение ваш драйвер моторов.

## Как это работает

1. **Поиск маркера** (`aruco_detector.py`). OpenCV находит на кадре маркер с
   нужным ID. Остальные маркеры игнорируются.
2. **Положение маркера.** По 4 углам маркера на кадре и его **реальному размеру**
   (в метрах) `solvePnP` вычисляет вектор от камеры до маркера. Из него берутся
   расстояние `distance` и азимут `bearing` (угол между осью камеры и
   направлением на маркер, `>0` - маркер правее).
3. **Логика** (`docking_logic.py`). Конечный автомат:

   | Состояние     | Что делает робот                                              |
   |---------------|----------------------------------------------------------------|
   | `SEARCHING`   | маркера не видно, вращается на месте (в сторону, где видел его в последний раз) |
   | `ALIGNING`    | маркер виден, но угол больше допуска, доворачивается на месте |
   | `APPROACHING` | едет вперёд, подруливая и замедляясь при приближении         |
   | `DOCKED`      | расстояние достигнуто, стоп (до вызова `reset()`)             |

   Короткую потерю маркера (блик, смаз кадра) робот пережидает стоя, а не едет
   вслепую. Между доворотом и ездой работает гистерезис, чтобы он не дёргался
   на границе допуска.
4. **Отправка команд** (`motor_controller.py`). Есть ROS 2 (`rclpy`): публикует
   `Twist` в `/cmd_vel`. Нет ROS (например, Windows): команды просто печатаются
   в консоль. Выбор автоматический.

## Файлы

| Файл                  | Назначение                                                     |
|-----------------------|----------------------------------------------------------------|
| `main.py`             | точка входа: камера, детектор, логика, отправка команд         |
| `config.py`           | **все настройки**: размер маркера, ID, камера, скорости, пороги |
| `aruco_detector.py`   | поиск маркера и расчёт его положения                            |
| `docking_logic.py`    | конечный автомат подъезда                                       |
| `motor_controller.py` | отправка скоростей: ROS 2 `/cmd_vel` или печать в консоль       |
| `generate_marker.py`  | создаёт PNG с маркером для печати                               |
| `test_detector.py`    | проверка без камеры и без робота                                |
| `requirements.txt`    | зависимости Python                                              |

## Установка

### Windows / ноутбук (тесты без робота)

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

Нужен именно **`opencv-contrib-python` версии 4.7 или новее**. Если раньше
ставили `opencv-python`, сначала удалите его: `pip uninstall opencv-python`.
Оба пакета одновременно не работают.

### Ubuntu 22.04 + ROS 2 Humble (на роботе)

```bash
source /opt/ros/humble/setup.bash
python3 -m venv --system-site-packages .venv
source .venv/bin/activate
pip install "numpy<2" "opencv-contrib-python>=4.7,<4.12"
```

`--system-site-packages` нужен, чтобы в окружении был виден `rclpy` из ROS.
Версии `numpy<2` и OpenCV до 4.12 выбраны, чтобы не конфликтовать с пакетами
ROS Humble, собранными под numpy 1.x. Проверка: `python -c "import rclpy, cv2; print(cv2.__version__)"`.

## Маркер

1. Создайте файл для печати (по умолчанию ID 0, 15 см, словарь `DICT_4X4_50`):

   ```bash
   python generate_marker.py                      # -> marker_id0_15cm.png
   python generate_marker.py --id 3 --size-cm 20  # другой ID и размер
   ```
   Готовый файл на 15 см уже лежит в проекте: `marker_id0_15cm.png`.
2. Печатайте в масштабе **100%** («реальный размер», не «по размеру страницы»)
   на матовой бумаге. Глянец даёт блики, и маркер хуже читается.
3. **Измерьте линейкой чёрный квадрат** (без белой рамки) и впишите точное
   значение в `config.py` -> `MARKER_SIZE_M`. Вся точность расстояния зависит
   от этого числа: ошибка в 1 см при размере 15 см даёт ошибку примерно 7% в расстоянии.
4. Наклейте на ровную жёсткую основу (картон, пластик) на зарядной станции на
   высоте камеры, лицом к направлению подъезда. Мятый или изогнутый лист даёт
   ошибки.

Если меняете ID или словарь, то меняйте `TARGET_ID` и `ARUCO_DICTIONARY` в
`config.py` вместе с маркером.

## Запуск

```bash
python main.py                  # с окном видео (есть монитор)
python main.py --no-window      # без окна, статус печатается в консоль (SSH)
python main.py --dry-run        # ROS не используется, команды только печатаются
python main.py --camera 1       # другая камера
```

Остановка: `Ctrl+C` (или `q` в окне видео). При выходе роботу отправляется
нулевая скорость.

**Первый запуск на реальном роботе:** поднимите колёса или отключите моторы от
драйвера и смотрите, что публикуется:

```bash
ros2 topic echo /cmd_vel
```

Знаки должны быть такими: маркер правее - `angular.z < 0` (поворот вправо),
маркер левее - `angular.z > 0`. Если ваш робот поворачивает наоборот,
исправьте знак там, где принимаются команды, а не в логике.

## Настройка

Всё в `config.py`:

- `MARKER_SIZE_M`, `TARGET_ID`, `ARUCO_DICTIONARY` - маркер (см. выше);
- `CAMERA_INDEX`, `FRAME_WIDTH`, `FRAME_HEIGHT` - камера;
- `CAMERA_MATRIX`, `DIST_COEFFS` - калибровка камеры (см. ниже);
- `CMD_VEL_TOPIC` - топик команд;
- `DOCKING_PARAMS` - дистанция остановки, допуск по углу, скорости, коэффициенты.

Скорости по умолчанию осторожные (`max_linear` 0.15 м/с, `max_angular` 0.5 рад/с).
Подбирайте их под вашего робота постепенно.

`dock_distance` - расстояние **от камеры до маркера**. Если контакты зарядки
находятся не там, где камера (а они не там), подберите значение так, чтобы
в момент остановки контакты оказались у станции.

## Калибровка камеры

Без калибровки расстояние считается по приблизительному углу обзора
(`HFOV_DEG`), и ошибка может доходить до десятка процентов. Для точной работы
откалибруйте камеру по шахматной доске (туториал OpenCV «Camera Calibration»
или в ROS пакет `camera_calibration`) и впишите результат в `CAMERA_MATRIX`
и `DIST_COEFFS` в `config.py`.

## Проверка без робота и без камеры

```bash
python test_detector.py
```

Скрипт рисует маркер в известных положениях и проверяет, что детектор
возвращает те же расстояния и смещения (на синтетических кадрах ошибка около 0.3%), что чужие ID
игнорируются, что строго фронтальный маркер не даёт `NaN`, и прогоняет
автомат состояний. Должно закончиться строкой `ИТОГ: ВСЁ ОК`.

## Ограничения

- Робот едет **на центр маркера** и не учитывает, под каким углом повёрнута сама
  станция. Если станция принимает робота только строго перпендикулярно,
  нужен точный исходный курс, либо доработка (выезд на перпендикуляр к
  маркеру).
- Точность проверена на синтетических кадрах. На реальном роботе она зависит
  от камеры, освещения, смаза при движении и качества печати. Для дальности
  используйте маркер покрупнее.
- Положение камеры относительно центра робота не учитывается.
- Если кадры перестали приходить, `main.py` останавливает робота, но
  аварийную остановку по таймауту команд лучше иметь и на стороне драйвера
  моторов.
- Для работы по SSH нужен запуск с `--no-window`: окно OpenCV по SSH не откроется.

## Частые проблемы

| Симптом | Что проверить |
|---------|---------------|
| `Ошибка: не удалось открыть камеру` | Номер камеры (`--camera`), права на `/dev/video0`, не занята ли камера другой программой |
| `В OpenCV нет cv2.aruco.ArucoDetector` | Установлен не тот пакет или старая версия: `pip install -U opencv-contrib-python`, без `opencv-python` |
| Маркер не находится | Правильный ли `TARGET_ID` и `ARUCO_DICTIONARY`; есть ли вокруг чёрного квадрата белая рамка; нет ли бликов; не слишком ли мал маркер на кадре |
| Расстояние неверное | `MARKER_SIZE_M` (измерьте линейкой), калибровка камеры |
| Робот крутится в другую сторону | Знак `angular.z` в вашем драйвере (см. «Запуск») |
| Робот дёргается около цели | Увеличьте `angle_tolerance_deg` или уменьшите `kp_angular` в `config.py` |
